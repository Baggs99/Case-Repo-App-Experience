## Goal

Server-rendered guest interviewer path in `webapp/`, per Mobile canvas **8a**
(the ONE designed web surface): (a) **link-gate** — a claim link opens with
ZERO app chrome, "Continue as guest" or "Log in"; (b) **console-lite** — clock,
serif read-aloud, ONE exhibit release, finalize & send feedback; (c)
**post-session** — "Keep this session on a record?" → B2 account upgrade →
"On the record." Vanilla templates + inline design-token styling. No frameworks,
no build step, no new migration (B2 shipped the schema).

## Architecture

New router `webapp/routes/guest_web.py` (registered with one `include_router`
line in `webapp/main.py`, additive). New standalone templates (NOT extending
`base.html` — base carries app nav/tab chrome; the gate is "zero chrome"):
`guest_gate.html`, `guest_console.html`, `guest_keep.html`, `guest_saved.html`.
One small ES module `webapp/static/js/caseroom/guest_console.js` (clock + release
+ finalize fetches). Reuse `console.js` `MasterClock` for the clock where the DOM
contract fits; otherwise a minimal self-contained tick.

**Entry & flow (all under `/g/` prefix):**
- `GET /g/claim/{claim_token}` — PUBLIC link-gate. Reads the open proposal by
  token (unguessable, `token_urlsafe(24)`); renders candidate name, their
  requested case, "your side provided" per 8a. `Continue as guest` = a same-page
  POST form; `Log in` = link to `/login?next=/g/claim/{token}`.
- `POST /g/claim/{claim_token}` — `require_auth_or_mint_guest` + `require_same_origin`.
  Calls `proposals_repo.claim_proposal(token, user.id, is_guest=user.is_guest)`
  (B2's exact minting/gating path), then 303-redirects to `/g/session/{session_id}`.
  On `TransitionError`/`RecapGateError`: `discard_minted_guest(request)` (B2
  orphan-reap) and re-render the gate with the error (409 copy).
- `GET /g/session/{session_id}` — console-lite. `require_session_participant`
  (B2 dependency — guest 403 on any session it is not a participant of; real
  non-participant 404). Interviewer seat only (candidate seat → redirect to the
  authed `/session/{id}` call page; guests only ever hold the interviewer seat
  on this path per B2). Renders clock, read-aloud (case framing + case-pack PDF
  link), exhibit-01 Release control, "End — finalize & send feedback".
- `GET /g/session/{session_id}/keep` — post-session. `require_session_participant`.
  Only reachable once state is `finalized` (else redirect back to console). If
  `user.is_guest`: "Keep this session on a record?" + upgrade form. If not a
  guest (logged-in claimer): "Saved to your record." (already on record — no
  upgrade; login variant not designed, canvas note).
- Upgrade posts to the EXISTING `POST /api/v1/auth/upgrade` (B2, `require_guest`).
  On success JS navigates to `/g/session/{session_id}/saved` → "On the record."

**State-change endpoints reused (all already `require_same_origin` + guest-aware):**
- Release exhibit: `POST /api/practice/{id}/reveals {exhibit_id}` (interviewer only).
- Finalize: `POST /api/practice/{id}/finalize {grade?}` → state `finalized`.
- Case-pack PDF (guest may open ONLY its own session's case): the existing
  `/api/cases/{case_id}/open-pdf` → `/files/cases/{case_id}` (B2 `require_case_access`).

## Global constraints (verbatim by reference)

backend-gap-execution.md §2 in full: parameterized SQL only; server-side
validation; **CSRF = the existing `require_same_origin` origin-check on every
state-changing handler** (this repo has NO token-CSRF — same-origin is the
pattern; all reused POST endpoints already carry it, and my POST `/g/claim`
adds it); auth guard on every route; **`require_session_participant` on every
console route**; guests never see candidate-private data (grades pre-finalize,
diagnostics, recommendations — none surfaced on any guest page); no placeholders;
4-line module docblock header (Purpose/Inputs/Outputs/Run); match repo style;
comments explain why. Design fidelity: staircase mark only (no emoji/icons),
square content corners, capsule glass, secondary = underline text, serif for
voice, tabular-nums timers, exact 8a copy where it is not persona data. NO new
migration; if one seems needed → STOP, report BLOCKED.

## Key data facts (verified)

- Cases have NO read-aloud/prompt text column (content is the PDF + encrypted
  exhibits). **Read-aloud binds to case framing** (title/type/difficulty) + a
  serif instruction line + the case-pack PDF link the interviewer reads from.
  Documented deviation DV-F10-1.
- `claim_proposal`: guest may claim ONLY an instant (no proposed_times),
  case-set proposal whose `from_role='candidate'` → claimer becomes interviewer,
  returns `{session_id, accepted:True, needs_negotiation:False}`.
- `require_session_participant(session_id, request) -> User` in `webapp/auth/guest.py`.
- Upgrade requires a whitelisted school-domain email (B2 `upgrade_guest` →
  `InvalidEmailDomain` 400). Canvas's "school optional for interviewers" is NOT
  in B2 — surface B2's 400 message; documented as inherited constraint DV-F10-2.

## Tasks

### Task 1 — Link-gate (router + gate template + proposal preview read fn)
Files: `webapp/routes/guest_web.py` (new), `webapp/templates/guest_gate.html`
(new), `webapp/repositories/proposals.py` (additive read fn
`get_open_by_claim_token(token) -> Optional[dict]` returning
`{proposal_id, from_name, from_role, case_id, case_title, is_instant}` via a
parameterized SELECT joining users for `from_name` and cases for `case_title`;
returns None when token unknown/claimed), `webapp/main.py` (one include_router
line, additive).
- `GET /g/claim/{token}`: 404-render a neutral "This link is no longer active"
  gate when `get_open_by_claim_token` is None (no existence disclosure beyond
  the token holder). Otherwise render 8a link-gate: kicker "YOU'VE BEEN ASKED
  TO INTERVIEW", candidate `from_name`, "THEIR REQUEST" = case_title, "YOUR
  SIDE" = "Script, answer key, timer — all provided", serif aside verbatim,
  `Continue as guest` (POST form, `require_same_origin` satisfied same-origin),
  `Log in — keep it on your record` → `/login?next=…`. Zero chrome; own
  `<style>`/inline tokens; fonts via the same Google-Fonts approach base.html
  uses. If `current_user` and not guest → the gate's guest CTA still claims as
  that user (real claim).
- `POST /g/claim/{token}` (deps: `require_same_origin`; user via
  `require_auth_or_mint_guest`): claim → 303 `/g/session/{sid}`; on error reap +
  re-render gate with 409 message, HTTP 409.
- TDD: `tests/test_f10_guest_web.py` — GET gate 200 + key markup for a seeded
  open candidate-role instant proposal; GET unknown token → 200 neutral
  "no longer active" (or 404 — pick one, assert it); POST claim as anon mints a
  guest cookie + 303 to `/g/session/{sid}`; POST with a scheduled/case-less token
  → 409 + no orphan guest row left (assert users count unchanged). Per-test
  cleanup (delete created proposals/sessions/guest users). Commit.

### Task 2 — Console-lite (page + JS clock/release/finalize)
Files: `webapp/templates/guest_console.html` (new),
`webapp/static/js/caseroom/guest_console.js` (new), `guest_web.py` (add route).
- `GET /g/session/{id}` (`require_session_participant`): resolve role; if role !=
  interviewer → 303 to `/session/{id}` (authed call page owns the candidate seat).
  If state already `finalized` → 303 `/g/session/{id}/keep`. Boot JSON:
  `{sessionId, caseId, caseTitle, exhibits:[{exhibit_id, idx}], peerName}` (first
  exhibit only for the ONE release; from `case_exhibits.list_manifest`). Render
  per 8a gIsLive: glass clock pill (blink dot + `{{time}}` tabular), "GUEST
  CONSOLE" tag, `MARKET SIZING · CANDIDATE: {peer}` kicker → case_title, READ
  ALOUD serif block (case framing + "Read from the case pack"), the case-pack
  PDF row (opens `/api/cases/{caseId}/open-pdf`), EXHIBIT 01 row with `Release`
  → `SENT · mm:ss`, bottom `End — finalize & send feedback`.
- JS module: start clock on load (reuse `console.js` MasterClock if DOM fits,
  else minimal tick — tabular). `Release` → `fetch POST /api/practice/{id}/reveals
  {exhibit_id}` same-origin JSON; on 200 swap to `SENT · <clock>`. `End` →
  confirm → `fetch POST /api/practice/{id}/finalize {}` → on 200
  `location='/g/session/{id}/keep'`. All fetches `credentials:'same-origin'`,
  `X-Requested-With`-free (origin header suffices).
- TDD: extend `test_f10_guest_web.py` — GET console 200 + markup (clock pill,
  READ ALOUD, EXHIBIT 01, End button) for the guest interviewer of a live
  session; guest of session A gets 403 on `/g/session/{B}` (IDOR); real
  non-participant 404; reveal endpoint reachable by the guest interviewer (200)

### Task 3 — Keep-on-record + upgrade + on-the-record
Files: `webapp/templates/guest_keep.html`, `webapp/templates/guest_saved.html`
(new), `guest_web.py` (add routes), small inline upgrade JS (in template or the
module).
- `GET /g/session/{id}/keep` (`require_session_participant`): if state !=
  `finalized` → 303 `/g/session/{id}`. If `user.is_guest`: render 8a gIsPost —
  "FEEDBACK SENT — {PEER} HAS IT", "Keep this session on a record?", THIS
  SESSION / OTHERWISE rows, `Create an account` (reveals upgrade form: email +
  password) posting to `/api/v1/auth/upgrade`, `Not now` → `/g/session/{id}/saved?guest=1`
  (a plain "closed" acknowledgement — nothing persists). If NOT guest: "Saved to
  your record." (already on record).
- Upgrade JS: `fetch POST /api/v1/auth/upgrade {email,password}` same-origin; 200
  → `location='/g/session/{id}/saved'`; 400/409 → inline error text (surface
  B2's message, e.g. bad domain / weak pw / taken email).
- `GET /g/session/{id}/saved` (`require_session_participant`): 8a gIsMade —
  staircase draw + "On the record." + serif line. `?guest=1` variant (came from
  "Not now", still a guest): a gentle "This tab holds it until you close it"
  close state (no false "on the record" claim).
- TDD: extend tests — keep page for a finalized guest session shows the upgrade
  ask; upgrade with a valid seeded-domain email flips `is_guest=False` (assert
  via DB) and the guest can then hit `/g/session/{id}/saved` 200; upgrade bad
  domain → 400 surfaced; non-guest participant sees "Saved to your record."
  variant. Commit.
