## Locked architecture (decisions the tasks build on)

**A1 — The console IS the interviewer's LIVE seat.** In `SessionView`, the interviewer `live`
branch renders a new size-class-aware `InterviewerConsoleView` (phone 8b `.compact` / tablet 1a
`.regular`) in place of `InterviewerLiveView`. Candidate live stays dark/unchanged. The console
overrides to the LIGHT palette at its root (`.dsTheme(.light)`, exactly as DebriefView overrides the
dark cover). This SUPERSEDES F5's dark `InterviewerLiveView` (canvas 4a interviewer) as the real
live-interviewer path — the two are competing designs for the same moment; the brief ("extend the
interviewer seat", "tablet hero = THE flagship") selects the console. `InterviewerLiveView` +
its `liveInterviewerStandalone` fixture are RETAINED (F5 artifact, not deleted) to keep the suite
green. → OWNER-VISUAL deviation.

**A2 — All state-changing work flows through the EXISTING plumbing.** Scoring/exhibits/reveal/
finalize go through the shared `RubricViewModel` (already owned by SessionView, shared with
DebriefView). Score → `score(itemId:points:)`; tap-same-to-clear writes `points:0` (backend treats
absent==0 in `compute_grade`, and the rail avg (A3) excludes 0 → equivalent to "unscored", no remove
API needed). Exhibits → `rubricViewModel.exhibits`. Release → `reveal(exhibitId:)`. "Finalize & send"
(top-bar + last-stage button) → `moveToDebrief()` — the SINGLE finalize/close path stays F5's
DebriefView (the interviewer's real finalize control lives there; the console button is a review step,
not an instant send — confirm DebriefView's finalize is labelled so the button doesn't read as
lying). No duplicate `/finalize` from the console; scores carry over via the shared VM.
Transport/WebRTC/signaling/reveal-crypto BYTE-IDENTICAL (HARD RULE).
**Integration point (rv-finding #3): repoint at the `liveContent` level, NOT `roleLiveContent`** —
the interviewer branch must short-circuit BEFORE SessionView's outer `VideoCallView` (height 300)
wrapper so a remote console doesn't double-render video above its own 224h feed rail; the console
owns its media surface (A7) internally. Candidate branch unchanged.
**Exhibit-ref mapping (rv #11):** script `e1/e2/e3` → `ExhibitMeta.idx` 0/1/2 → `.exhibitId` for
`reveal(exhibitId:)`; the PDF page-02 "Release" (T5) calls the SAME reveal and shows the SAME
SENT·mm:ss as the script's e1 row.

**A3 — Template-agnostic rubric.** The console renders whatever template `RubricViewModel` loads.
Real backend = **5 dims / max 5** (structure, quant, insight, communication, synthesis). Screenshot
fixture = canvas-faithful **12 dims / max 10** (via a stub service, exactly like F5's `liveRubric`).
RUBRIC — LIVE rail shows ALL template items (current-stage dims ink, others slate). **The running
avg (rv-finding #4) is a LOCAL arithmetic mean of scored dims (points>0 only, unscored/0 excluded) —
NOT `gradePreview`** (which lags the 800ms autosave and is on the backend grade scale); this matches
the canvas's instant "N AVG" / "NO SCORES YET". Left "SCORE THIS STAGE" shows the current stage's
items. **The cell scale is derived from `item.maxPoints` (rv #1): header "1 TO {maxPoints}", per-dim
readout "{pts} / {maxPoints}"** — never a hardcoded 10. `ScoreCells(count: item.maxPoints, size:)` —
shared F0 component at .medium (24pt tablet left) / .small (16pt rail) / phone strip; renders
correctly at 5 and 10. → the 12-vs-5 gap is an OWNER-VISUAL deviation (canvas mock vs shipping
rubric; enrich backend template later or accept 5).

**A4 — Authored ConsoleScript (client-side).** No backend stage-script / case-pack endpoint exists.
The 7-stage script (read-aloud + guidance[] + exhibit-refs), CAP = 45 min, and the 3 authored PDF
pages are authored client-side content — the canvas Case-07 Nordic script, verbatim from Tablet 1a's
`STAGES`/`DIMS`/PDF markup. Phone = 6 stages (drops BEHAVIORAL, per 8b).
**Stage→template-item resolution has TWO modes (rv-finding #2):**
- **Tablet** (stacks all of a stage's dims, canvas 1a line 656): per-stage UNION dim-keys (canvas
  keys ∪ real backend ids); any template item unclaimed by a stage falls to a catch-all (CLOSE, which
  stacks) → every dim scoreable.
- **Phone** (ONE `SCORE — {dim}` strip per stage, canvas 8b line 201): the map is **1:1 — each real
  template dim on a DISTINCT phone stage, NO catch-all reliance** (6 phone stages ≥ 5 real dims;
  Clarify may carry none → its score block hidden). A phone stage never shows >1 dim. Phone assumes a
  ≤6-dim rubric (the shipping rubric is 5); >6-dim rubrics are a phone limitation (documented) — the
  phone fixture is the real-shaped ~5-dim template, NOT the 12-dim tablet fixture.
- Coverage tests assert every real template dim is surfaced by the RENDERED score UI (not just the VM
  list) on both size classes.
→ follow-up: a backend case-pack/script source when >1 case ships.

**A5 — Recall is local.** No recall/un-reveal endpoint; transport frozen. Recall clears the
interviewer's local SENT·mm:ss marker + restores Release; it does NOT un-broadcast (reveal is
one-way). → documented deviation.

**A6 — Clocks are view-local** (extending InterviewerLiveView's stopwatch pattern). Master clock:
tap-to-run, counts up from 0:00 (canvas 12:34/11:30 are demo seeds), `N LEFT` = CAP − elapsed
(turns green under 5 min, "OVER CAP" past it), 2px cap-progress bar, SENT·mm:ss = master-clock value
captured at release. Segment timer: independent Start/Pause + "Stop · log" appends "Segment 0N" laps.
ALL numerals tabular (reject-list poster children: master clock, segment timer, SENT·mm:ss, scores).

**A7 — Candidate feed** reuses F5 media pieces (`PeerVideoPane`/`VideoCallView`/`RemoteMediaSlot`):
LIVE chip + candidate name tag + self-view (118×66). Remote video when active; striped placeholder
otherwise and in shots. Transport untouched.

**A8 — B4 counterpart-recommendations** are a NEGOTIATION-phase input (pick sources), already
consumed by F5. The console (post-case-settlement, per canvases 8b/1a) surfaces no rec picker.
Documented; no console wiring.

## Reject-list guardrails (every task, reviewer-enforced)
No icons/emoji (StaircaseMark only), square content corners (capsule glass only), underline
secondaries (never outlined boxes), ≤1 glass hero/screen, tabular clock/timer/scores, NO population
counts. **Greens (rv #10): the ≤3-greens rule has an OWNER-CANVAS exception for this flagship —
§1-sanctioned greens (LIVE dot, N-LEFT under-5, SENT·mm:ss, READ-ALOUD/SCORE kickers, filled cells,
rail avg, RUNNING) are all legitimate; reviewers judge against the canvas, not a literal count.**

"Recall", "Display PDF — always here" (tablet) / "Display PDF" (phone), "SCORE THIS STAGE — 1 TO
{maxPoints}" (tablet — scale from template, NOT literal 10) / "SCORE — {dim}" (phone),
"Collects into the rubric rail →", "GUIDANCE — NOT READ ALOUD", "STAGE N OF 07/06 — READ ALOUD",
"SEGMENT TIMER", "RUNNING", "Stop · log", "SEGMENTS LOGGED", "Segment 0N",
"Nothing logged yet — stop the clock to keep a segment.", "CANDIDATE FEED", "RUBRIC — LIVE",
"NO SCORES YET" / "{avg} AVG", "CASE PACK — INTERVIEWER COPY · 8 PAGES", "The script keeps scoring;
this is the paper.", "‹ Back to script", "‹ Previous page" / "Next page ›", "PAGE 0N OF 08" (p3 "—

Tokens only (no hex / Color(red:) outside token files). info.properties never INFOPLIST_KEY_*.
