# F4 — Library · Implementation Plan

Date: 2026-07-17 · Phase lead worktree: /Users/thomaskgould/dev/fe-f4 · Branch: fe/f4-library

## Goal
Rebuild the LIBRARY tab (phone canvas 5a, tablet canvas 2c master–detail 1fr/470px) as a
casebook-row browser + case detail, binding to the pinned `/api/v1/cases*` contract (B3
`avg_rating`/`run_count`/`done_for_you` + `open_count`/`done_count`). Implement the retired-done
rules (Design Decisions §0.4): type chips + Everything/Not done/Done toggles + "N OPEN · N DONE"
live count; open rows first, retired rows greyed below a "DONE — YOURS TO INTERVIEW WITH" divider;
detail flips CTA to "Case someone with this" and shows a faint "Get re-cased anyway — won't count
toward diagnostics". Detail: rating+runs aggregate, your history, case-pack PDF row ("It knows.").

## Architecture
- **Networking** (`ios/CaseRoom/Networking/`): extend `CaseSummary`/`CaseDetail` Codable with
  B3 aggregates; new `LibraryPage` wrapper carrying `open_count`/`done_count`; `CasesService`
  gains `library(query:) -> LibraryPage`. `sessions(scope:"recent")` (exists) feeds history.
- **View model** (`ios/CaseRoom/State/LibraryViewModel.swift`, new): fetches the page, maps API
  rows → `LibraryCase` (view type with derived kicker/meta/ordinal + optional decorations),
  applies the type-chip + done-toggle filters (done partition from `done_for_you`), builds the
  divider + counts, tracks tablet selection. `CasesViewModel` is retired/replaced.
- **Views** (`ios/CaseRoom/Views/`): `CasesListView` rewritten to canvas 5a (phone) with a
  `NavigationStack(path: AppRouter.shared.libraryPath)` and an iPad size-class branch to the 2c
  master–detail. `CaseDetailContent` (new, shared) renders the detail body; `CaseDetailView`
  (rewritten) is the phone push wrapper (loads + hosts content); the tablet right pane hosts the
  same content for the selected row.
- **Fixtures** (DEBUG only): a `-LibraryFixtures` launch arg injects a stub `CasesService` +
  `SessionsService` seeded with the Decisions §3/§7 canonical 8 cases (from the tablet `CASES`
  array) so screenshots render the retired divider / tags / RECOMMENDED states. Live screens bind
  to `APIClient.shared`. Mirrors F1's `-DevLogin` + `PreviewProfileService` precedent.

  `.glassChip()`, `.tabularNumbers()`, `DSPressStyle`, `AnyTransition.dsRise`, `StaircaseMark`.
  `DSTextStyle`: `.h1Tab`(28/800), `.cardTitle`(20/700), `.rowTitle`(14/600), `.rowTitleStrong`
  (14.5/700), `.kicker`(10/600 caps), `.meta`(11.5), `.serif(_:italic:weight:)`.
- F1 router: `AppRouter.shared` (`@Observable @MainActor` singleton); `libraryPath: [AppRoute]`;
  `go(to: .caseDetail(id))` selects `.library` and appends `.caseDetail(id)`. Mount
  `NavigationStack(path:)` bound to `libraryPath`, `navigationDestination(for: AppRoute.self)`.

## Task 2 — LibraryViewModel + LibraryCase mapping
Files: `ios/CaseRoom/State/LibraryViewModel.swift` (new), delete
`ios/CaseRoom/State/CasesViewModel.swift`, `ios/CaseRoomTests/LibraryViewModelTests.swift` (new).

Do:
1. `protocol CasesService { func library(query: CaseQuery) async throws -> LibraryPage;
   func caseDetail(id: Int) async throws -> CaseDetail }` + `extension APIClient: CasesService {}`.
2. `enum LibraryType: CaseIterable { case all, marketEntry, profitability, ma, sizing }` with
   `.label` ("All"/"Market entry"/"Profitability"/"M&A"/"Sizing") and `.caseTypeFilter: String?`
   (the value passed to `CaseQuery.caseType`; `all` → nil). **Mapping note:** the canvas fixture
   uses short codes (entry/profit/ma/sizing) but the LIVE DB `case_type` values are full strings
   (e.g. "Profitability"). The chip filters the API by passing `.caseTypeFilter` as `case_type`;
   set `.caseTypeFilter` to the DB spelling ("Market Entry"/"Profitability"/"M&A"/"Market Sizing"
   — confirm exact DB casing via `SearchFilters`/seed; case_type match is exact-equality server-side).
   Document any DB-vs-label mismatch in the report; the fixture stub maps by the short code.
3. `enum LibraryDone: CaseIterable { case everything, notDone, done }` with `.label`.
4. `struct LibraryCase: Identifiable, Equatable` view type: `id, ordinal (String "0N"), kicker
   (CASE TYPE · SCHOOL YEAR, upper), title, meta, done (Bool), avgRating (String, "—" if nil),
   runCount (Int), recommended (Bool=false), scheduledNote (String?=nil), historyLine (String?),
   historyScore (String?), pdfLabel (String), previewUrls ([String]=[]), pdfUrl (String?)`.
   Derivation from `CaseSummary`: kicker = `[case_type, "\(source_school) \(source_year)"]`
   uppercased joined " · " (omit missing parts); meta = `[difficulty, "rated by \(runCount)
   candidates"]` joined " · "; ordinal = zero-padded (total − index) — DECORATIVE, document.
5. `@Observable final class LibraryViewModel`:
   - state: `type: LibraryType = .all`, `done: LibraryDone = .everything`, `page: LibraryPage?`,
     `cases: [LibraryCase]`, `selectedID: Int?` (tablet), `isLoading`, `errorMessage`.
   - `load()`: builds `CaseQuery(caseType: type.caseTypeFilter, limit: 200)`, fetches `library`,
     maps to `[LibraryCase]` (recommended/scheduledNote nil live), optionally fetches recent
     sessions once and title-matches for detail history (or fetch history lazily in the detail —
     your call; keep the list query lean). Sets counts from the page.
   - `filteredRows`: applies the done toggle client-side over `done_for_you` (notDone → open only;
     done → done only; everything → both); returns an ordered `[LibraryRow]` enum
     (`.row(LibraryCase)` / `.divider(String)`): open rows first, then — IF both open and done rows
     exist under the active filter — a `.divider("DONE — YOURS TO INTERVIEW WITH")`, then done rows.
   - `countLine: String` = `"\(openCount) OPEN · \(doneCount) DONE"` (from the page — reflects the
     type filter, NOT the done toggle; the toggle is a view of the same set).
   - `selectedCase: LibraryCase?` (tablet — first row if none selected, per canvas fallback).
6. Tests (stub `CasesService`): everything/notDone/done partition correct; divider present only
   when both groups non-empty; countLine format; type filter passes the right `case_type`; kicker/
   meta derivation; empty → no rows. Assert NO population count leaks into any string.
Run: LibraryViewModelTests green. Commit "Add LibraryViewModel with retired-done partitioning".
