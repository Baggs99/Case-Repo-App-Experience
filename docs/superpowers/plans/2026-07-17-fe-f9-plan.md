## Backend contract (bgap-b5-report.md — REPORTS OVERRIDE BRIEFS)

The design "passcode keypad" maps to the **email OTP** endpoints (not the sign-up LINK — the
link is the web path; a 6-digit keypad is the native equivalent and the report ships it):

- `POST /api/v1/auth/otp/request` — same-origin, unauth. Always `202 {"status":"ok"}` (no
  enumeration). Code issued only for existing user OR registry domain; dev writes email to
  `output/emails/`.
- `POST /api/v1/auth/otp/verify` — same-origin, unauth. `200 {"user":{...}}` + **session
  cookie**, or `401`. **Provisions a school user for a new registry email.**
- `PUT /api/v1/profile` — required + same-origin. `display_name ≤100`, bio ≤2000,
  linkedin_url ≤300. (Account-completion display name.)
- `POST /api/v1/groups/join` — required + same-origin. body `{invite_code}` → group row or
  `404` "Unknown invite code". (Group-join step.) **Endpoint is B6, not B5** — cite
  `bgap-b6-report.md` (webapp/routes/groups.py:69). Response = `{id,name,school_id,invite_code,
  role,already_member}`; `JoinedGroup` Codable decodes a deliberate 3-of-6 subset
  `{id,name,already_member}` (Swift ignores extra keys).
- `GET /auth/google` · `GET /auth/linkedin` — browser routes, **503 without creds +
  WEBAPP_SESSION_SECRET** (not provisioned — ORCHESTRATION §8.1). Callback 302s to `/` with a
  session cookie.

Registered users: seed provides `a/b/c@yale.edu` / password `caseroom-dev-1`; registry
domains = yale.edu / umich.edu / chicagobooth.edu.

### KNOWN UNCERTAINTIES / FLAGS (carry into report — do NOT invent new patterns to hide them)
1. **Canvas 1d is stale + truncated.** All onboarding copy/layout is authored from the §2-1d
   prose + F0 tokens + the 8a/3-series look. Every string is lead-authored; flag as such.
2. **STEP mapping.** 5 progress steps chosen: (1) email, (2) passcode, (3) account,
   (4) group, (5) done; welcome is the pre-step intro. Judgment call — flag.
3. **OAuth native return path (impossible by construction, not just un-provisioned).** B5's
   OAuth callback 302s to `/` (https) and sets a *web* session cookie. `ASWebAuthenticationSession`
   watches for a redirect matching a native `callbackURLScheme`; a 302 to `/` never matches, so
   the completion handler never fires (sheet dead-ends). Separately the session runs in
   SafariViewService with its own cookie jar, so even a successful web login's cookie never
   reaches APIClient's `HTTPCookieStorage`. So live native OAuth cannot work today regardless of
   creds. We ship the buttons + a protocol-injected `OAuthStarter` (testable, mocked), open
   `/auth/google|linkedin` via `ASWebAuthenticationSession`, and FLAG as a Thomas follow-up
   (§8.1): backend must add a **native-scheme callback redirect + a token/cookie hand-back**,
   AND provision creds. Buttons are proven by fixture shots + VM tests, not a live round-trip.
4. Post-verify the user is authenticated server-side (cookie) but the onboarding flow holds
   the returned `User` locally and does NOT flip `SessionStore.isAuthenticated` until the
   final "Enter" — otherwise RootShell would swap the onboarding cover for the shell and drop
   account/group steps. Final step calls `SessionStore.bootstrap()` (cookie is set → `/me`
   returns the user → authenticated).

## Tasks

### Task 1 — Plumbing: OnboardingService + models + OAuthStarter + SessionStore hook (opus)
Files: `Networking/APIClient.swift`, `Networking/OnboardingOAuth.swift` (new),
`State/SessionStore.swift`, `Networking/Models.swift` (models), tests
`CaseRoomTests/OnboardingServiceTests.swift`.
- Protocol `OnboardingService { func requestOTP(email:) async throws; func verifyOTP(email:
  code:) async throws -> User; func joinGroup(inviteCode:) async throws -> JoinedGroup }`.
  APIClient conforms: `/api/v1/auth/otp/request` (POST body `{email}`), `/api/v1/auth/otp/verify`
  (POST body `{email,code}` → `{user}`), `/api/v1/groups/join` (POST body `{invite_code}`).
  `verifyOTP` maps `401` → `APIError.unauthorized`; `joinGroup` maps `404` → a typed
  `OnboardingError.unknownInviteCode`. **`verifyOTP` decodes a `{ user: User }` wrapper and
  returns `.user`** (the route returns `{"user":{...}}`, not a bare User).
- `JoinedGroup` Codable = `{id, name, already_member}` (matches groups.py `join_by_code`).
- `OAuthStarter` protocol `{ func start(provider: OAuthProvider) async throws }` +
  `WebAuthOAuthStarter` using `ASWebAuthenticationSession` against
  `baseURL/auth/<provider>` (import `AuthenticationServices`); `OAuthProvider {google,linkedin}`.
  Live start throws `OnboardingError.oauthUnavailable` on 503 / cancel. (Callback-scheme gap
  FLAGGED in the docblock — Thomas follow-up.)
- `SessionStore.finishOnboarding()` → `await bootstrap()`.
- Tests (URLProtocol stub, existing test pattern): request/verify/join decode + status
  mapping (202/200/401/404); `finishOnboarding` flips `isAuthenticated` when `/me` succeeds.
- Evidence: tests green + build. No screen.
- **Per-task before build: run `xcodegen generate` in `ios/` (static .xcodeproj must pick up
  new files) and commit the project.** (Applies to every task adding a file.)
